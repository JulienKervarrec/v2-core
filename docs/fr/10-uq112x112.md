# 10. UQ112x112 : les nombres à virgule fixe

Solidity n'a pas de nombres décimaux. Un rapport de réserves comme `reserve1 / reserve0` en division entière donnerait zéro dès que le numérateur est le plus petit — inutilisable pour un prix.

`libraries/UQ112x112.sol` règle le problème en vingt lignes. Le format est annoncé par son nom : un nombre non signé (**U**), 112 bits de partie entière, 112 bits de partie fractionnaire, logé dans un `uint224`.

```solidity
uint224 constant Q112 = 2**112;

function encode(uint112 y) internal pure returns (uint224 z) {
    z = uint224(y) * Q112;   // ne déborde jamais
}

function uqdiv(uint224 x, uint112 y) internal pure returns (uint224 z) {
    z = x / uint224(y);
}
```

`encode` décale la valeur de 112 bits vers la gauche, créant la place pour la partie fractionnaire. La division qui suit conserve donc 112 bits de précision au lieu de tout perdre.

Le commentaire « never overflows » n'est pas un vœu : `y` est un `uint112` et la cible un `uint224`, la multiplication par `2**112` tient toujours. C'est aussi pourquoi les réserves sont plafonnées à `uint112` — le choix du chapitre 4 et celui-ci sont le même choix.

Le consommateur de l'oracle doit diviser par `2**112` pour retrouver un nombre ordinaire.
